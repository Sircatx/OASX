# 日历（周视图）

选择配置后点击“总览”下方的“日历”，查看周一至周日的任务与时间。
上周、下周按钮切换日期范围，“本周”回到当前周，刷新按钮重新读取配置。
页面每 15 秒自动刷新；总览的运行状态、运行任务、排队或等待列表变化后，日历会在 400 毫秒防抖后重新加载。
今天的任务沿用总览同一份调度状态，显示运行中、排队中或等待中；排队任务不承诺准确开跑时间。
积压任务列在今天并标注原定日期和时间，后续间隔预测从当前时间重新推算。读取日历不会修改调度配置。
“每周运行星期”可多选，至少保留一天；日历展开所有选定星期，调度器选择最近的选定日期。旧版单星期配置自动兼容。
每天的任务列表独立滚动并按需渲染；点击日期查看秒级明细，点击任务进入设置。

前端每次只请求七天的数据：

```text
GET /{script_name}/calendar?start=YYYY-MM-DD
```

服务端将 start 对齐到所在周的星期一，返回 start、end、events 和 warnings。
需要配套的 OnmyojiAutoScript 周历接口（本地后端提交 3213aff7）。
已停用的任务不会显示。下一次时间来自配置，周期推算显示为“预计”或“每周计划”。
每天同一任务的成功执行合并为一条绿色记录，显示“已完成 N 次”，时间为当天最近一次成功时间；后续计划单独保留。日期明细也显示成功次数，每日汇总分别显示计划数量和成功次数。
任务需明确标记成功且以 TaskEnd 正常结束才计一次；自定义调度时间的结界蹭卡、挂卡和狩猎战在实际成功位置标记，计数不改变下次执行时间。失败、跳过、异常恢复、只调整计划时间不计成功。
寮突破单独按已结束的战斗计数（胜负都计，未进入战斗或中断不计），显示“共战斗 N 次”；每日汇总中的寮突破战斗数与其他任务成功次数分开。所有时间只显示当天最后一次。
次数按北京时间日期和配置方案隔离，保存在后端 config/global/task_history.sqlite3，重启后保留。历史记录可通过后端 dev_tools/backfill_calendar.py 按日志中明确的完成证据补录，默认仅预览，--apply 会先备份数据库，重复补录不会增加次数；已经停用的任务仍保留真实历史。
实际执行仍受脚本开关、队列及任务内部规则影响。计划读取保持只读，成功记录不可用时提示并继续显示计划。

验证：前端静态检查、Flutter 3.27.1 Windows AOT 编译、七天数据范围以及真实窗口中的周切换（含跨月）、刷新、每日独立滚动、秒级明细和任务设置跳转均通过。
